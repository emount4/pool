# «Бассейн» · КР №3

Сервер КР №3 использует посещение как основную сущность, дорожку как справочник и существующую таблицу клиентов для выбора посетителя. Архивирование меняет видимость записи, а отмена освобождает интервал. Приоритет обычного посещения стандартный, индивидуального повышенный, индивидуального от 90 минут высокий.

## Запуск базы и backend

1. Запустите Docker Desktop.
2. Скопируйте корневой `.env.example` в `.env`, если файла ещё нет. Задайте `POOL_DB_PASSWORD` и случайный ключ `POOL_JWT_SECRET_BASE64` (не менее 32 байт до кодирования).
3. Выполните из корня репозитория `powershell -ExecutionPolicy Bypass -File .\backend\start-compose.ps1`.
4. Откройте `http://localhost:8080/` и войдите. Порт задаётся `POOL_APP_PORT`. Текущая рабочая конфигурация этого компьютера использует `18089`.
5. Проверьте `/actuator/health`. После входа администратором откройте Swagger из раздела «Управление».

Первый запуск создаёт отдельный том Compose. Flyway создаёт первоначальную схему и расширяет её. Обычная остановка Compose сохраняет данные.

В PowerShell 7 ключ можно сгенерировать командой `[Convert]::ToBase64String([System.Security.Cryptography.RandomNumberGenerator]::GetBytes(32))`. Миграция V9 создаёт администратора с логином `admin` и паролем `Admin123`. В существующей базе V9 однократно устанавливает этот пароль и роль ADMIN для учётной записи admin. Пароль хранится как BCrypt-хеш. Последующая смена пароля сохраняется при перезапуске.

## Вход через API

- `POST /api/auth/login` принимает `username` и `password`, возвращает access JWT на 15 минут и refresh-токен.
- `POST /api/auth/register` принимает `username`, `displayName`, `password` и `passwordConfirmation`. Новая учётная запись получает роль VIEWER и сразу входит в систему. Назначение прав редактирования и администрирования доступно администратору.
- Защищённые запросы принимают заголовок `Authorization: Bearer <accessToken>`. `GET /api/auth/me` возвращает текущую учётную запись.
- `POST /api/auth/change-password` принимает `oldPassword` и `newPassword` и выдаёт новую пару токенов. До смены временного пароля доступ к рабочим данным закрыт.
- `POST /api/auth/refresh` и `POST /api/auth/logout` принимают `refreshToken` в JSON. После обновления сохраняйте токен из нового ответа.
- Веб-клиент добавляет `X-Pool-Client: web`. Refresh-токен передаётся через HttpOnly cookie с SameSite Strict, access-токен хранится в памяти страницы. После перезагрузки страницы клиент обновляет сессию. Для Android сохраняется JSON-контракт с отдельным refresh-токеном.
- Swagger UI и OpenAPI доступны администратору. В браузере сначала войдите в веб-приложение. Для вызова защищённых операций в Swagger получите access JWT запросом `/api/auth/login` и вставьте его в **Authorize**.

## Журнал посещений

- `GET /api/visits` принимает `query`, `lane`, `status`, `individual`, `priority`, `tag`, `archived`, `from`, `to`, `duration` и `comparison` (`EQ`, `LT`, `LTE`, `GT`, `GTE`). Параметры страницы: `page`, `size` (до 100), `sort` (`visitDate`, `durationMinutes`, `visitNumber`) и `descending`.
- `GET /api/clients?query=...` ищет клиента. `GET /api/visits/available-slots` принимает `date`, `duration`, `clientId` и при редактировании `except` с UUID текущего посещения.
- В справочнике изначально восемь дорожек. Новые дорожки получают номера начиная с 9. Отключённые дорожки не предлагаются при бронировании. Выбор новых дорожек доступен в REST API КР №3, поскольку интерфейс JavaFX рассчитан на номера 1–8.

## Перенос базы КР №1

Работайте с резервной копией. Восстановите её в отдельную базу до первого запуска backend. Убедитесь, что схема содержит исходные таблицы `system_users`, `clients` и `visits` из `database/schema.sql`. Проверьте пересечения записей клиента и дорожки. При пересечении V2 откатится целиком. Уже установленные ограничения V2 сохраняются.

Для первого запуска backend на проверенной копии укажите её JDBC URL и задайте `SPRING_FLYWAY_BASELINE_ON_MIGRATE=true`, `SPRING_FLYWAY_BASELINE_VERSION=1`. Flyway зафиксирует исходную схему, затем применит миграции начиная с V2. После успешной миграции уберите оба параметра. Старые числовые ID и внешние ключи сохраняются. Существующие посещения получают UUID и номера вида `VIS-123`.

## CSV, заметки и массовые действия

Заметки доступны по `/api/visits/{id}/notes`. Для изменения заметки передаётся её версия. Массовый запрос `POST /api/visits/bulk` содержит `ids` (до 100 UUID) и `action`: `ARCHIVE`, `RESTORE`, `STATUS`, `ADD_TAG` или `REMOVE_TAG`. Для соответствующих операций передайте `status` либо `tag`. Каждая запись обрабатывается в отдельной транзакции, ответ содержит результат по каждому UUID. Переходы статуса ограничены отменой будущей записи и возвращением отменённой будущей записи в план.

Экспорт CSV учитывает фильтры и сортировку журнала. Импорт принимает файл до 1 МБ и 500 строк. Формат заголовков совпадает с экспортом. `POST /api/visits/import/preview` принимает multipart `file` и `mode` (`NEW_ONLY` или `UPSERT`). Предпросмотр действует час и принадлежит создавшему его пользователю. `POST /api/visits/import/apply` принимает JSON с `previewId`. Корректные строки применяются отдельно, ошибочные возвращаются с причинами. Повторное применение успешных строк сохраняет результат. Импорт соблюдает правила будущих запланированных посещений.

`GET /api/analytics/summary` принимает необязательные даты `from` и `to`. Активными в сводке считаются неархивные записи. Аудит доступен по `GET /api/admin/audit` с `query`, `page`, `size` и `ascending`.

## Проверки

В разделе «Swagger и тесты» задания прямо требуются четыре проверки: загрузка Spring Context, бизнес-правило или вычисляемый показатель, фильтр или поиск, политика паролей или другой элемент безопасности. В backend оставлены эти четыре проверки.

Из корня проекта выполните `pwsh -File backend/test-postgres.ps1`. Скрипт запускает отдельную PostgreSQL, выполняет четыре обязательных теста и останавливает тестовые контейнеры. Для ручного запуска `mvn -f backend/pom.xml clean test` с интеграционными проверками задайте `POOL_TEST_DB_ENABLED=true`, `SPRING_DATASOURCE_URL`, `SPRING_DATASOURCE_USERNAME`, `SPRING_DATASOURCE_PASSWORD`, `POOL_JWT_SECRET_BASE64`. Используйте отдельную тестовую базу.

Фронтенд собирается командами `npm ci` и `npm run build` в каталоге `frontend`. Docker собирает React и включает результат в Spring Boot JAR. Для локальной разработки запустите backend отдельно, затем `npm run dev`.
