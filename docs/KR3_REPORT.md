# КР №3 · Отчёт о реализации проекта «Бассейн»

Дата проверки — 23 ноября 2026 года.

## Результат

В репозиторий добавлены Spring Boot backend и веб-клиент React с TypeScript. PostgreSQL и backend запускаются через Docker Compose. Собранный React включается в JAR и открывается по тому же адресу, что и REST API.

В текущей локальной конфигурации приложение доступно по адресу http://localhost:18089/. Доступны регистрация и вход. Миграция V9 создаёт готовую учётную запись admin с паролем Admin123. Пароль хранится в виде BCrypt-хеша.

## Соответствие функциональным требованиям

| Пункт задания | Реализация |
| --- | --- |
| 1. Авторизация и учётные записи | Регистрация и вход, три роли VIEWER/OPERATOR/ADMIN, access JWT на 15 минут, refresh-сессии на 14 дней. Хеш refresh-токена хранится на сервере. Обновление заменяет refresh-токен, выход отзывает сессию. Получение текущего пользователя, смена пароля, обязательная замена выданного временного пароля, BCrypt, ограничение неудачных входов. Отключение пользователя отзывает сессии. При самостоятельной регистрации пользователь получает роль VIEWER. |
| 2. Основная сущность | Посещение. Публичный UUID, уникальный номер, название и описание, клиент и дорожка, статус, длительность, признак индивидуального занятия, теги, вычисляемый приоритет, createdAt/updatedAt, version и архив. |
| 3. CRUD и архив | Получение списка и карточки по UUID, создание и изменение, архивирование, восстановление, окончательное удаление архивной записи администратором. При редактировании проверяется версия, при конфликте возвращается 409. |
| 4. Поиск, фильтрация, сортировка, пагинация | Поиск по номеру, названию, имени, фамилии и телефону клиента. Фильтры по дорожке, статусу, индивидуальному занятию, приоритету, тегу, архиву, датам и длительности. Сравнения EQ/LT/LTE/GT/GTE. Сортировка по дате и времени, длительности или номеру. Серверная пагинация до 100 строк. Пользовательские значения передаются параметрами, поля сортировки ограничены списком. |
| 5. Справочная сущность | Справочник дорожек, создание, изменение, включение и отключение администратором. Отключённые дорожки исключаются из подбора времени и новых записей. |
| 6. Заметки | Список заметок посещения, создание, изменение с проверкой версии и удаление. Сохраняются автор, время создания и изменения, признак закрепления. |
| 7. Массовые операции | Список до 100 UUID. Архив, восстановление, допустимая смена статуса, добавление и удаление тега. Отдельная транзакция и результат для каждого UUID. Ошибка одной записи сохраняет результаты остальных. |
| 8. CSV | Экспорт с текущими фильтрами и сортировкой. Отдельные запросы preview и apply. Количество корректных и ошибочных строк, причины ошибок по строкам. Режимы NEW_ONLY и UPSERT по номеру посещения. Проверка файла хранится в PostgreSQL и привязана к пользователю. Повторное применение успешной строки возвращает прежний результат. При применении повторяются проверки занятости и версии. |
| 9. Аналитика | Общее количество, действующие и архивные записи, индивидуальные занятия, средняя длительность. Группировки по дорожкам, статусам и приоритетам. Дополнительно реализован период по датам посещений. |
| 10. Пользователи | Пагинация, создание с временным паролем, изменение имени, логина, набора ролей и активности. Сброс пароля. Запрет самоотключения и снятия с себя роли администратора. |
| 11. Аудит | Входы, неудачные попытки, выходы, смена и сброс паролей, изменения пользователей, посещений, дорожек, заметок, массовые действия и импорт. Пользователь, тип события, тип сущности, UUID, время, описание и Correlation ID. Поиск, сортировка по времени и пагинация доступны администратору. |
| 12. Валидация и ошибки | Bean Validation, ограничения строк, диапазонов и форматов. Контроллеры возвращают DTO. JSON ошибок содержит code, message, fields и correlationId. Реализованы ответы 400/401/403/404/409, ограничение входов возвращает 429. Неожиданные ошибки логируются, клиент получает безопасное сообщение. |

Обычный просмотр и выгрузка доступны наблюдателю. Оператор может менять рабочие данные, вести заметки, импортировать и выполнять массовые действия. Администратор дополнительно управляет пользователями и дорожками, просматривает аудит и окончательно удаляет записи. Требование смены временного пароля проверяется сервером.

## PostgreSQL, Flyway и развёртывание

- Java 21 в Docker, Spring Boot 3.5.5, PostgreSQL 17, Maven, Spring Security, Spring Data JPA, Bean Validation и Actuator.
- Девять миграций Flyway. V1 создаёт исходную схему КР №1, V2 защищает от пересечений, V3 расширяет посещения, V4 добавляет веб-учётные записи, V5 позволяет добавлять дорожки, V6 добавляет заметки, теги и аудит, V7 хранит результаты проверки CSV, V8 добавляет поисковые индексы и UUID дорожек для аудита, V9 создаёт admin / Admin123.
- Hibernate использует ddl-auto: validate. В PostgreSQL заданы внешние ключи, уникальность, CHECK и ограничения пересечения времени. Для поиска добавлены индексы pg_trgm.
- Compose запускает два сервиса с отдельными проверками готовности. Порты опубликованы на localhost, данные сохраняются в постоянном томе.
- Swagger UI и OpenAPI защищены ролью администратора. Вход в веб-приложение позволяет открыть Swagger из раздела «Управление».
- Для тестов PostgreSQL добавлен backend/test-postgres.ps1. Он создаёт отдельный проект Compose и восстанавливает переменные окружения после завершения.

## Веб-интерфейс

Реализованы регистрация и вход, обязательная смена выданного временного пароля и обычная смена пароля, журнал посещений, карточка, создание клиента, подбор свободного времени, заметки, массовые действия, импорт и экспорт CSV, аналитика, управление пользователями и дорожками, просмотр аудита.

Для оформления использован landing-page-design с учётом рабочего интерфейса. Светлый фон и бирюзовый акцент продолжают оформление JavaFX. Используется Manrope, задана шкала типографики и отступов, предусмотрены фокус клавиатуры, состояния загрузки, пустых списков и ошибок. На узком экране фильтры свёрнуты, широкие таблицы прокручиваются внутри своего контейнера. Добавлены favicon, ссылка перехода к содержимому и страница 404.

Access-токен веб-клиента хранится в памяти. Refresh-токен передаётся через HttpOnly cookie с SameSite Strict. Работа с этой cookie требует специального заголовка веб-клиента, межсайтовые запросы с ним не разрешены. Для будущего Android-клиента доступен JSON-контракт с refresh-токеном в теле запроса.

## Сохранённые правила бассейна

Сеансы проходят с 07:00 до 22:00, начало и длительность кратны 30 минутам, длительность от 30 до 180 минут. Запись в прошлое и пересечения одного клиента или дорожки запрещены. Отменённое посещение освобождает интервал. Редактирование и отмена разрешены до начала запланированного сеанса. Backend регулярно обновляет статусы по часовому поясу бассейна.

## Принятые решения

1. Основной сущностью выбрано посещение, справочником — дорожка. Существующие таблицы clients, visits и system_users используются как основа.
2. Числовые ID сохранены для прежних связей и JavaFX. В REST API посещения идентифицируются публичными UUID.
3. Обычное посещение имеет стандартный приоритет, индивидуальное — повышенный, индивидуальное от 90 минут — высокий.
4. Архивирование сохраняет статус записи. Занятость освобождается отменой. Окончательно удалить можно архивное посещение.
5. Изначально доступны восемь дорожек. Новые получают номера начиная с 9. Настольный интерфейс рассчитан на дорожки 1–8.
6. Для BCrypt созданы отдельные веб-учётные записи. Старые PBKDF2-хеши JavaFX сохранены. Пользователь может зарегистрироваться самостоятельно, администратор назначает дополнительные права. Пользователи, созданные администратором, получают временный пароль.
7. Импорт соблюдает правила будущих запланированных посещений. Допустимо применение корректных строк файла с отдельным возвратом ошибок остальных строк.
8. Текущий запуск использует отдельную демонстрационную базу. Браузерная проверка создала проверочных клиентов, посещения и заметки.

## Границы проверки

Перенос проверен на отдельной тестовой схеме, воспроизводящей КР №1. Реальная прежняя база пользователя в этом запуске не была доступна. Инструкция переноса приведена в backend/README.md.

Архив Student Hub не приложен. Его отдельный запуск как преподавательского примера не проверялся. Реализован собственный backend по теме «Бассейн».

## Сценарий защиты

1. Запустить backend/start-compose.ps1, показать контейнеры и health.
2. Войти администратором, затем показать доступ наблюдателя и оператора.
3. Создать клиента и посещение с подбором дорожки.
4. Показать поиск, несколько фильтров, сортировку и пагинацию.
5. Показать отказ при пересечении и конфликте version.
6. Добавить и изменить закреплённую заметку, выполнить массовое действие с тегом.
7. Архивировать и восстановить запись.
8. Выгрузить CSV, проверить файл с ошибками, применить корректные строки, показать UPSERT.
9. Открыть аналитику и выбрать период.
10. Создать пользователя, сменить временный пароль, отключить доступ.
11. Открыть аудит и Swagger, показать миграции и ограничения PostgreSQL.
12. Запустить тесты и объяснить проверяемые правила.
