# Бассейн — настольное приложение JavaFX

Переработка https://github.com/emount4/pool (исходный коммит `a6286ff`).
Java 21 · JavaFX 21 · FXML/CSS · PostgreSQL · JDBC · Maven.

## Быстрый запуск готовой сборки

1. Установите **Java 21** (64-битную, например Temurin JDK 21) и **Docker Desktop**.
2. Полностью распакуйте ZIP. Не запускайте файлы непосредственно внутри архива.
3. Запустите Docker Desktop и дождитесь готовности.
4. **Windows:** дважды щёлкните `start.bat`.
   **Linux / macOS:** откройте терминал в распакованной папке и выполните `chmod +x start.sh run.sh mvnw`, затем `./start.sh`.
5. Войдите одной из учебных учётных записей:

| Роль | Логин | Пароль |
| --- | --- | --- |
| Администратор | `admin` | `Admin123` |
| Оператор | `operator1` | `Operator123` |

Это учётные записи именно проекта «Бассейн». Реквизиты `admin@example.org` из ТЗ относятся к отдельному преподавательскому примеру.

`start.bat` / `start.sh` запускает **только PostgreSQL в Docker**, ожидает готовности БД и открывает JavaFX **на компьютере**. `run.bat` / `run.sh` запускает только клиент, если база уже работает. Приложение обращается к PostgreSQL напрямую через JDBC, REST-сервер ему не нужен.

В каталоге `app` уже находятся собранный JAR и библиотеки. Maven, интернет и отдельная установка JavaFX для запуска клиента не требуются. Интернет нужен Docker для первого скачивания образа PostgreSQL. Java 21 и Docker не вложены в ZIP.

В сборке есть библиотеки для Windows x64, Linux x64, macOS Intel/Apple Silicon. Архитектура установленной Java должна соответствовать системе; Windows ARM может использовать Java x64 через эмуляцию ОС. На Linux требуется графическая сессия и системные GTK3-библиотеки. Архив не является нативным `.exe`-инсталлятором.

## Подключение к существующей базе КР №1

Названия и структура основных таблиц сохранены: `clients`, `visits`, `system_users`.
Отредактируйте **`database.properties` в корне проекта**:

```properties
db.url=jdbc:postgresql://localhost:5433/pool_db
db.username=postgres
db.password=postgres
```

Не запускайте `schema.sql` или `data.sql` поверх существующей базы. Приложение не пересоздаёт таблицы и не перезаписывает учётные записи. При полностью пустой таблице пользователей экран входа предложит создать первого администратора.

Приоритет настроек: переменные `DB_URL`, `DB_USERNAME`, `DB_PASSWORD` → внешний `database.properties` → встроенный `src/main/resources/database.properties`. Для нестандартной схемы можно добавить `db.schema=имя_схемы` (одно имя). Свойство JVM `-Dpool.config=путь` задаёт другой внешний файл. Настройки читаются заново по кнопке «Повторить подключение» на экране входа.

`compose.yaml` использует имя проекта `pool` и существующее имя тома `pool_postgres_data` внутри проекта. Если прежний Docker Compose запускался с другим именем проекта, используйте его через `docker compose -p ИМЯ ...` либо укажите адрес уже работающей базы в настройках клиента. Не создавайте новый том вместо старого, если нужны данные КР №1.

### Защита от одновременной записи на одно время

Для новой БД ограничение автоматически устанавливается третьим SQL-скриптом. Для существующей БД примените один раз **недеструктивную миграцию**:

PowerShell:

```powershell
Get-Content -Raw -Encoding UTF8 .\database\migrations\002_no_overlaps.sql | docker compose exec -T db psql -U postgres -d pool_db -v ON_ERROR_STOP=1
```

Linux / macOS:

```sh
docker compose exec -T db psql -U postgres -d pool_db -v ON_ERROR_STOP=1 < database/migrations/002_no_overlaps.sql
```

Миграция добавляет `btree_gist` и два EXCLUDE-ограничения: занятость клиента и дорожки. Отменённые записи не блокируют время, соседние интервалы разрешены. При уже существующих пересечениях миграция целиком откатывается: сначала исправьте такие записи. Для установки расширения нужны права владельца БД / администратора. Без миграции проверки сервисного слоя работают, но старый сервер не защищён от гонки нескольких экземпляров приложения.

## Docker

```sh
docker compose up -d --wait db
docker compose ps
docker compose exec db pg_isready -U postgres -d pool_db
docker compose down
```

Обычная остановка сохраняет данные. Не используйте `down -v` для базы, которую хотите сохранить.

При первом создании тома выполняются `schema.sql`, `data.sql`, затем миграция. Загружаются 8 клиентов, 20 посещений и 2 пользователя. Даты посещений считаются относительно дня создания базы. Исходные 45-минутные тестовые сеансы приведены к 60 минутам, чтобы соответствовать правилу шага 30 минут. Это изменение касается только начальных данных новой базы.

`.env` / `.env.example` задаёт порт и пароль Docker. Если меняете эти значения, обновите также `database.properties`. Изменение `.env` не меняет пароль в уже созданном томе PostgreSQL.

## Что умеет приложение

- **Клиенты:** просмотр, добавление, редактирование, удаление с подтверждением; поиск по имени, фамилии, телефону и email; фильтры возраста и наличия email; переход к посещениям выбранного клиента.
- **Посещения:** полный CRUD; выбор клиента по имени и телефону, выбор свободного интервала и дорожки; отмена будущей записи; просмотр контактов выбранного клиента.
- Поиск посещений по данным клиента; одновременные фильтры по статусу, дорожке, клиенту и периоду. Даты применяются кнопкой «Применить даты». Сброс очищает все фильтры.
- Сортировка нажатием на заголовки таблиц. `Shift` + щелчок добавляет ещё одно поле; даты и числа сортируются как даты и числа.
- **Статистика:** 9 показателей, период и диаграмма по дорожкам. Показатели: клиенты, посещения, посещения сегодня, четыре статуса, средняя длительность, популярная дорожка.
- **Экспорт:** Excel `.xlsx` и CSV UTF-8 с BOM через стандартное окно выбора файла. Выгружаются только текущие отфильтрованные строки в текущем порядке. Статистика экспортируется со своим периодом.
- **Пользователи:** администратор создаёт пользователей, меняет логин/роль/пароль и блокирует доступ. Оператор не видит этот раздел; сервис также проверяет роль.
- Все обращения к базе и запись файлов выполняются вне JavaFX Application Thread. Ошибки показываются в формах или диалогах, а не вместо интерфейса в консоли.

### Бизнес-правила

Бассейн работает 07:00–22:00. Старт и длительность кратны 30 минутам, длительность 30–180 минут, дорожки 1–8. Нельзя создать запись в прошлом, одновременно записать одного клиента или занять одну дорожку дважды. Редактирование и отмена доступны только для ещё не начавшегося запланированного посещения. Прошедшие и отменённые записи сохраняются в истории; их можно удалить после подтверждения.

Кнопка обновления и вход в главное окно актуализируют статусы: прошедшие посещения завершаются, начавшиеся переходят в «Идёт сейчас». Постоянного автоматического таймера нет — используйте «Обновить и актуализировать».

Имя и фамилия: 2–100 символов; телефон: 7–15 цифр (допускается форматирование); email: до 255 символов; дата рождения: не в будущем, возраст до 120 лет. Контакты проверяются на уникальность. Клиент с посещениями не удаляется. Нельзя заблокировать себя или убрать последнего активного администратора.

## Сборка из исходников

Требуется JDK 21; Maven Wrapper уже включён. Первый запуск сборки скачивает Maven и зависимости.

```sh
./mvnw clean verify
./mvnw javafx:run
./mvnw -Pportable clean package
```

На Windows замените `./mvnw` на `mvnw.cmd`. Последняя команда создаёт `target/pool-desktop-2.0.0.zip` с исходниками и готовой сборкой для четырёх платформ. После изменения кода запускайте `mvnw javafx:run`, либо пересоберите ZIP: `run.bat` читает уже собранный JAR из `app`.

IntelliJ IDEA: открыть `pom.xml`, выбрать Project SDK 21 и запустить Maven goal `javafx:run`. Основная точка входа — `ru.mirea.pool.Main`. Прежняя консоль сохранена отдельно как `ConsoleMain` для сравнения с КР №1 и не используется обычными файлами запуска.

`Dockerfile` предназначен только для сборки артефактов через Docker BuildKit, не для запуска графического клиента.

## Проверки

```sh
./mvnw test
./mvnw -Pui-tests test
```

Первый вариант проверяет сервисы, правила, статистику, фильтры, пароли и экспорт. Второй дополнительно загружает и отрисовывает все FXML в headless JavaFX/Monocle. Headless-профиль рассчитан на Linux и не нужен для обычного запуска приложения.

Для проверки реального JDBC задайте `POOL_TEST_DB_URL`, при необходимости `POOL_TEST_DB_USER` и `POOL_TEST_DB_PASSWORD`, и выполните `mvnw test`. Интеграционный тест создаёт отдельную случайную схему `pool_test_*` и удаляет только её. Рекомендуется отдельная тестовая БД; для миграции нужны права на `CREATE EXTENSION`. Дополнительный UI-сценарий включается переменной `POOL_UI_DB_URL` и ожидает учебные данные и стандартный учебный пароль администратора; используйте только тестовую БД.

Результаты конкретной проверки этой поставки: `docs/TEST_REPORT.md`. Снимки интерфейса: `docs/screenshots/`.

## Структура и защита

| Каталог / файл | Назначение |
| --- | --- |
| `presentation/fx/controller` | Контроллеры экранов и форм; координация действий |
| `src/main/resources/fxml` | 9 FXML-экранов и форм |
| `src/main/resources/css/pool.css` | Всё визуальное оформление |
| `application/service` | Валидация, бизнес-правила, статистика и фильтры |
| `domain/model`, `domain/repository` | Модели и контракты репозиториев |
| `infrastructure/database` | JDBC, PreparedStatement, закрытие ресурсов |
| `infrastructure/export` | Excel и CSV |
| `database` | Схема, тестовые данные, миграция |
| `src/test` | Модульные, JDBC и JavaFX-проверки |
| `docs/REQUIREMENTS.md` | Соответствие пунктам ТЗ и сценарий демонстрации |

Список таблиц — `ObservableList`, фильтрация — `FilteredList`, порядок — `SortedList`, связанный с comparator `TableView`. SQL находится только в инфраструктуре, формы вызывают сервисы. Для связывания FXML и Java используются `fx:controller`, `fx:id` и `onAction`.

Пароли пользователей хранятся как PBKDF2-хеши. Пароль БД хранится в конфигурации, не в Java-классах. Это учебная локальная система; стандартные учётные записи предназначены для демонстрации. Журнал неожиданных ошибок — `pool-desktop.log` рядом с файлами запуска.

## Если что-то не запускается

- **Нет подключения:** запустите Docker Desktop, выполните `docker compose ps`, проверьте порт `5433` и настройки клиента. Затем нажмите «Повторить подключение».
- **Порт занят:** остановите только ненужный сервер либо измените `POSTGRES_PORT` и JDBC URL. Данные удалять не нужно.
- **Неверный пароль пользователя:** учебные пароли действуют для начальных данных этого проекта. Старые пользователи и пароли из прежней БД сохраняются.
- **Ошибка версии Java:** `java -version` должен показывать 21 или новее; для сборки используйте JDK 21.
- **Не удаётся сохранить Excel:** закройте файл в Excel либо выберите другое имя/папку.
- **Нет свободного времени:** выберите другую дату или длительность; после изменения условий нажмите «Найти свободное время».

Официальные справочники: [JavaFX](https://openjfx.io/openjfx-docs/), [pgJDBC](https://jdbc.postgresql.org/documentation/use/), [Docker Compose](https://docs.docker.com/compose/).
